# S3-compatible module

`s3` backs up one bucket (optionally below a prefix) from AWS S3, MinIO, or a
compatible endpoint. Objects are streamed with `GetObject`; restores use bounded
5 MiB multipart parts and never create a local staging object.

Required parameter: `bucket`. Optional parameters: `endpoint`, `region`,
`prefix`, `access_key`, `secret_key`, and `path_style`. `path_style` is a
tri-state: leave it unset to get path-style addressing whenever a custom
`endpoint` is configured (what MinIO needs), or set it explicitly to override
that default in either direction. Destination policy is explicit:
`create_bucket=true` permits a missing bucket and `--overwrite` (or
`overwrite: true` in YAML) permits collisions. A created bucket carries the
location constraint its region requires, so creation works outside
`us-east-1`.

`--overwrite` deletes the stale keys in the target prefix **before** the first
payload byte arrives, and replaces the surviving ones in place as they stream.
A run that fails midway therefore leaves a mix of already-replaced and
not-yet-replaced objects — never reported as verified, but not the previous
state either. Restore into a fresh prefix and switch over if the previous
contents must survive a failed attempt.

The plan records keys, sizes, ETags, user metadata and the HTTP entity headers
that are part of the object: `Content-Type`, `Content-Encoding`,
`Cache-Control`, `Content-Disposition`, `Content-Language` and
`x-amz-website-redirect-location`. All of them are restored and compared during
read-back — the payload digest cannot notice their loss, since the bytes are
identical either way. Bucket policy is restored when source credentials can read
it. Zero-byte objects and Unicode/`+`/`%` keys are supported. Multipart sizing
grows automatically so large objects stay below S3's 10,000-part limit.

Object listing pages on the continuation token alone, never on `IsTruncated`.
A provider that omits that flag would otherwise truncate the plan at the first
page — and because the plan, the destination scope and the read-back all derive
from the same listing, such a run would certify itself as a verified copy of a
bucket it had only partly read.

Before any bytes are read, source analysis rejects versioned buckets, tagged
objects, non-default ACLs, non-`STANDARD` storage classes, SSE headers, an
`Expires` header (S3 reports it as an HTTP date but accepts a timestamp on
write, so it cannot be reproduced faithfully), and objects over 5 TiB: this
build does not silently drop those features. The destination re-runs the same
fidelity gate over the received plan and additionally rejects a plan whose item
sizes disagree with its object catalog, or whose objects collide on one
destination key — it never trusts the source's own gate.

## Completion proof

The destination lists the restored prefix and requires its key set to match
exactly, including absence of stale keys after `--overwrite`. It HEAD-checks
size, content type and user metadata, compares the translated bucket policy
semantically, and GET-reads every object to reproduce item and payload BLAKE3
commitments. Missing, extra, unreadable or changed objects fail completion.
The MinIO matrix also verifies zero-byte/special-name objects, overwrite cleanup,
aborted multipart cleanup and source immutability.

## Optional AWS smoke

With normal AWS SDK/CLI credentials configured, set `RUST_BACKUP_AWS_E2E=1`,
`RUST_BACKUP_AWS_SOURCE_BUCKET`, and `RUST_BACKUP_AWS_DEST_BUCKET`, then run
`bash e2e/s3_aws_test.sh`. It writes unique per-run keys and deletes those exact
keys on exit. Without the explicit gate the script prints `SKIP`; secrets are
never passed on argv.
