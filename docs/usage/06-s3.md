# 06 — S3 e MinIO

Copia di un bucket (eventualmente limitata a un prefisso) fra endpoint
S3-compatibili: AWS S3, MinIO e simili. Gli oggetti vengono letti con
`GetObject` e riscritti con multipart a parti limitate (5 MiB, alzate solo
quanto serve per restare sotto il limite di 10 000 parti): nessun file di
appoggio locale, in nessun momento.

## Caso minimal

MinIO locale, credenziali nell'ambiente, bucket già esistente sulla
destinazione:

```bash
export RUST_BACKUP_ACCESS_KEY=minioadmin RUST_BACKUP_SECRET_KEY="$MINIO_PASSWORD"

rust-backup s3 source \
  --to 127.0.0.1:7835 --channel s3 \
  --endpoint http://127.0.0.1:9000 --bucket sorgente

rust-backup s3 destination \
  --to 127.0.0.1:7835 --channel s3 \
  --endpoint http://127.0.0.1:9000 --bucket destinazione --yes
```

Su AWS il minimo è ancora più corto, perché l'endpoint è implicito e le
credenziali possono arrivare dalla catena standard AWS:

```bash
rust-backup s3 source      --to coord:7835 --channel s3 --region eu-south-1 --bucket sorgente
rust-backup s3 destination --to coord:7835 --channel s3 --region eu-south-1 --bucket destinazione --yes
```

## Caso tipico in produzione

```bash
RUST_BACKUP_ACCESS_KEY="$SRC_ACCESS_KEY" RUST_BACKUP_SECRET_KEY="$SRC_SECRET_KEY" \
rust-backup s3 source \
  --to https://coordinatore.example:7835 --channel s3-prod --secret-file /run/secrets/rb \
  --region eu-south-1 --bucket bucket-sorgente --prefix produzione/

RUST_BACKUP_ACCESS_KEY="$DST_ACCESS_KEY" RUST_BACKUP_SECRET_KEY="$DST_SECRET_KEY" \
rust-backup s3 destination \
  --to https://coordinatore.example:7835 --channel s3-prod --secret-file /run/secrets/rb \
  --region eu-south-1 --bucket bucket-ripristino --prefix recuperato/ \
  -P create_bucket=true --yes
```

## Parametri del modulo

| Flag | Variabile | Default | Lato | A cosa serve |
|------|-----------|---------|------|--------------|
| `--bucket <nome>` | `RUST_BACKUP_BUCKET` | — (obbligatorio) | entrambi | bucket da leggere / in cui scrivere |
| `--region <regione>` | `RUST_BACKUP_REGION` | `us-east-1` | entrambi | regione AWS. Per MinIO va bene qualunque valore coerente con la configurazione del server |
| `--endpoint <url>` | `RUST_BACKUP_ENDPOINT` | nessuno (AWS) | entrambi | endpoint S3-compatibile, per esempio `http://minio:9000`. La sua presenza attiva di default l'indirizzamento path-style |
| `--prefix <prefisso>` | `RUST_BACKUP_PREFIX` | nessuno | entrambi | sorgente: copia solo le chiavi sotto quel prefisso. Destinazione: le chiavi vengono riscritte sotto questo prefisso (il prefisso sorgente viene tolto e sostituito) |
| `--access-key <chiave>` | `RUST_BACKUP_ACCESS_KEY` | catena AWS | entrambi | chiave d'accesso. Se omessa si usa la catena di credenziali standard AWS (variabili `AWS_*`, profilo, ruolo dell'istanza) |
| `--secret-key <chiave>` | `RUST_BACKUP_SECRET_KEY` | catena AWS | entrambi | chiave segreta. **Deve essere fornita insieme a `--access-key`**: una sola delle due è un errore di configurazione |
| `--path-style[=bool]` | `RUST_BACKUP_PATH_STYLE` | *non impostato* | entrambi | tri-stato: non impostato = path-style attivo quando è configurato un `--endpoint` (ciò che serve a MinIO); un valore esplicito vince sempre, quindi `--path-style=false` è rispettato anche con endpoint personalizzato |
| `--overwrite[=bool]` | `RUST_BACKUP_OVERWRITE` | falso | destinazione | autorizza la sostituzione di oggetti esistenti e la rimozione delle chiavi obsolete nel prefisso di destinazione |
| `-P create_bucket=true` | — | falso | destinazione | autorizza la creazione del bucket se manca. La creazione usa il vincolo di location richiesto dalla regione, quindi funziona anche fuori da `us-east-1` |

Valgono inoltre tutti i flag di trasporto di [02 — Trasporto](02-trasporto.md).
`--carriers` viene sempre ridotto a **1**: il multipart segue l'ordine stretto
del piano.

## Cosa viene copiato

Chiavi, contenuti, dimensioni, ETag, metadati utente e le intestazioni HTTP che
fanno parte dell'oggetto: `Content-Type`, `Content-Encoding`, `Cache-Control`,
`Content-Disposition`, `Content-Language` e `x-amz-website-redirect-location`.
Vengono ripristinate e confrontate durante la rilettura, perché il digest del
payload da solo non si accorgerebbe della loro perdita (i byte sono identici).
La policy del bucket viene copiata se le credenziali sorgente sanno leggerla.
Oggetti a zero byte e chiavi Unicode, con `+` o `%`, sono supportati.

Dettagli in [docs/modules/S3.md](../modules/S3.md).

## Cosa viene rifiutato prima di leggere un solo byte

L'analisi si ferma — non copia in silenzio una versione peggiore — se trova:

- bucket con **versioning** attivo;
- oggetti con **tag**;
- **ACL** non di default;
- classi di storage diverse da `STANDARD`;
- intestazioni di **cifratura lato server** (SSE): chiavi e header non sono
  portabili fra provider;
- l'intestazione `Expires` (S3 la riporta come data HTTP ma la accetta come
  timestamp in scrittura: non è riproducibile fedelmente);
- oggetti oltre 5 TiB.

La destinazione **ripete lo stesso controllo** sul piano ricevuto e rifiuta in
più un piano le cui dimensioni non coincidono con il catalogo o le cui chiavi
collidono a destinazione: non si fida mai del controllo fatto dalla sorgente.

## `--overwrite`: cosa distrugge e quando

Con `--overwrite` le chiavi obsolete del prefisso di destinazione (quelle che non
esistono nel piano) vengono **eliminate prima** che arrivi il primo byte, e le
altre vengono sostituite man mano che arrivano. Un'esecuzione fallita a metà
lascia quindi un misto di oggetti già sostituiti e non ancora sostituiti — mai
certificato come valido, ma nemmeno lo stato precedente. Per poter tornare
indietro: ripristinare su un prefisso nuovo e commutare dopo.

Senza `--overwrite`, se il prefisso di destinazione contiene chiavi estranee al
piano, il preflight fallisce:

```text
destination prefix contains stale objects not in the source: […]; use --overwrite to replace the scope
```

## Permessi necessari

- **Sorgente**: elencare il bucket (`ListBucket`), leggere gli oggetti
  (`GetObject`) e i loro metadati; facoltativamente leggere la policy del bucket
  (`GetBucketPolicy`) e lo stato di versioning, altrimenti la copia della policy
  viene semplicemente omessa.
- **Destinazione**: scrivere oggetti (`PutObject`), gestire il multipart
  (`CreateMultipartUpload`, `UploadPart`, `CompleteMultipartUpload`,
  `AbortMultipartUpload`), elencare e — con `--overwrite` — eliminare
  (`DeleteObject`); con `-P create_bucket=true` anche `CreateBucket`, e
  `PutBucketPolicy` se la policy va riprodotta.

## Anteprima senza trasferire nulla

```bash
RUST_BACKUP_ACCESS_KEY=… RUST_BACKUP_SECRET_KEY=… \

```

## In sessione YAML

```yaml
parallel_targets: 2
targets:
  - module: s3
    role: source
    transport: { to: coordinatore.example:7835, channel: s3-prod, secret: CAMBIAMI }
    params:
      region: eu-south-1
      bucket: bucket-sorgente
      prefix: produzione/
      access_key: CAMBIAMI
      secret_key: CAMBIAMI

  - module: s3
    role: destination
    transport: { to: coordinatore.example:7835, channel: s3-prod, secret: CAMBIAMI }
    params:
      region: eu-south-1
      bucket: bucket-ripristino
      prefix: recuperato/
      access_key: CAMBIAMI
      secret_key: CAMBIAMI
      create_bucket: true
      overwrite: false
    auto_accept: true
```

Modello pronto: [examples/s3-session.yml](../../examples/s3-session.yml).

## Errori frequenti

| Sintomo | Causa e rimedio |
|---------|-----------------|
| `s3.bucket must not be empty` | manca `--bucket` |
| `s3.access_key and s3.secret_key must be supplied together` | fornita una sola delle due chiavi |
| errori di firma/host con MinIO | manca `--path-style` (o manca `--endpoint`) |
| `IllegalLocationConstraint` o bucket assente | usare `-P create_bucket=true`, oppure creare il bucket a mano nella regione giusta |
| preflight: oggetti obsoleti nel prefisso | serve `--overwrite` oppure un prefisso di destinazione pulito |
| analisi rifiutata (versioning, SSE, tag, storage class) | vedi la sezione dei rifiuti: questa build non produce copie silenziosamente inferiori |
